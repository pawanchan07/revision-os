# BUILD SPEC — PERSONAL AI / PRODUCT / DATA PREPARATION MAP

## 0. WHAT THIS PRODUCT IS

Build a LOCAL, OFFLINE-FIRST web application called:

"Preparation Map"

This is my personal visual knowledge map for everything I am currently learning and preparing for.

This is NOT a generic course website.

This is NOT a linear curriculum.

This is NOT just a dashboard with cards.

It should feel like an interactive "map of my brain" / "map of my preparation".

The core experience:

I open the application.

I immediately see the complete landscape of everything I am learning.

I can visually understand how the topics connect.

I can click any topic.

A focused revision/explanation panel opens.

I can quickly understand:
- what it is
- why it exists
- what problem it solves
- a very simple real-world analogy
- the technical meaning
- how it connects to other concepts
- what tools are used
- where it is used in real products
- what I should know
- what I should learn next
- useful external resources

I should be able to jump between topics without losing the overall map.

The application must make it extremely easy to answer:

"What am I learning?"

"How does everything connect?"

"What have I already covered?"

"What should I revise?"

"What should I learn next?"

"If someone asks me about this topic, do I actually understand it?"

# 46. IMPORTANT CONTENT PRINCIPLE

Do not hide important concepts simply because they seem basic.

If something is fundamental, include it.

For example:

Do not assume I know:

- what an API is
- what JSON is
- what a vector is
- what a parameter is
- what a repository is
- what an embedding is
- what logits are
- what softmax is
- what inference means
- what a model checkpoint is
- what an endpoint is
- what a database index is
- what an ANN index is
- what a tokenizer is

Fundamentals are part of the map.

# 47. IMPORTANT LEARNING PRINCIPLE

Every concept should answer four questions:

WHAT?

WHY?

HOW?

WHEN?

For example:

WHAT is RAG?

WHY does RAG exist?

HOW does RAG work?

WHEN should I use RAG?

Then:

WHEN should I NOT use RAG?

# 51. DO NOT MAKE THIS A DAY-BY-DAY COURSE

IMPORTANT:

Do NOT organize the application into:

Day 1

Day 2

Day 3

etc.

This is a persistent knowledge map.

I may spend three days on RAG and then jump back to SQL.

The application should support non-linear learning.

# 52. FINAL QUALITY BAR

Before considering the application complete, verify:

- every major topic is represented
- every major topic is connected
- map navigation works
- search works
- filtering works
- topic pages work
- progress persists
- quick revision works
- deep dive works
- practice works
- external links work
- no broken navigation
- no blank pages
- no console errors
- local launch works
- no CDN dependency
- no deployment
- responsive UI works

The final product should feel like something I would genuinely open every day to orient myself before learning.

It should make the entire AI / product / data / strategy landscape feel understandable rather than overwhelming.

The application is successful if I can open it after several days away and immediately remember:

"Where I am."

"What I already know."

"What connects to what."

"What I should revise."

"What I should learn next."

And if I click a topic, I should be able to go from:

absolute beginner explanation

→ technical explanation

→ product perspective

→ practical example

→ tools

→ deeper resources

→ practice.

Build this as a serious, polished local product, not as a demo page.
